# BioMentor Agent 测试反馈指南

本指南用于比赛演示前的集中测试，帮助同学高效发现问题、统一反馈格式。

---

## 一、测试优先级

| 级别 | 说明 | 示例 |
|---|---|---|
| **P0** | 阻塞性问题，必须修复后才能演示 | 页面打不开、主线流程断、按钮无反应、文献支撑无法使用 |
| **P1** | 明显体验问题，影响比赛印象 | 文案不自然、布局明显错位、空状态不合理 |
| **P2** | 优化建议，不影响正常演示 | 文案优化、低优先级体验改进 |

---

## 二、测试路线

按以下顺序依次测试，每条路线完成后在反馈表中记录结果。

### 1. 主线闭环测试

```
/cases 
→ 点击案例卡片 
→ 查看详情弹窗 
→ 点击"带入答辩"或"进入科研实战"
→ 进入 /research?caseId=...
→ 查看 4 个科研训练任务
→ 点击"文献支撑"
→ 选择文献 provider
→ 查看检索结果
→ 生成文献支撑笔记
```

**验证点：**
- 页面能否正常打开
- 每个步骤是否有明确反馈
- 文献检索是否有结果返回
- 笔记是否成功生成

### 2. 全站页面巡检

依次访问以下页面，检查是否正常渲染、有无报错：

| 页面 | 路由 | 检查项 |
|---|---|---|
| 首页 | `/` | Hero 区域、导航、CTA 按钮 |
| 产业案例 | `/cases` | 卡片加载、搜索、筛选、详情弹窗 |
| 科研实战 | `/research` | 案例选择、任务生成、文献支撑 |
| 知识探索 | `/explore` | 知识点展示、测验生成 |
| 生物工具箱 | `/tools` | 工具列表、功能入口 |
| 知识图谱 | `/knowledge-map` | 图谱渲染、节点交互 |
| 拍照学练 | `/photo-learning` | 图片上传、知识匹配 |
| 学术答辩 | `/seminar` | 材料导入、答辩生成 |

### 3. 文案合规检查

浏览全站界面，确认**不出现**以下敏感词汇：

```
API
未配置
not_configured
provider
metadata
Evidence Link
evidence
demo
smoke
本地
后端
前端
环境变量
```

如果界面出现上述词汇，请按 P1 级别反馈。

### 4. 文献支撑测试

在 `/research` 页面选择一个科研任务卡，执行：

1. 点击"文献支撑"按钮
2. 观察文献列表是否加载
3. 选择一篇文献
4. 查看是否生成文献支撑笔记
5. 检查笔记内容是否合理

### 5. 学术答辩入口测试

从 `/cases` 页面点击"带入答辩"，验证：

1. 是否正确跳转到 `/seminar`
2. URL 参数是否正确传递
3. 答辩材料是否包含案例信息

## 三、反馈格式

每条反馈按以下格式提交：

```text
页面：（如 /cases, /research?caseId=case-004）
操作：（如 点击案例卡片 → 查看详情 → 点击"进入科研实战"）
期望结果：（如 应跳转到科研实战页面并生成4个任务卡）
实际结果：（如 页面跳转到空白，控制台报错 xxx）
截图/报错：（粘贴截图或复制控制台错误信息）
严重程度：P0 / P1 / P2
是否阻塞展示：是 / 否
建议修复：（可选，如有建议可填写）
```

### 反馈示例

**示例 1（P0）：**

```text
页面：/research?caseId=case-004
操作：点击 mRNA 疫苗案例 → 进入科研实战 → 查看任务卡
期望结果：应显示 4 个科研训练任务
实际结果：页面加载后只显示 2 个任务，另外 2 个位置空白
截图/报错：Console 无报错，页面截图见附件
严重程度：P0
是否阻塞展示：是
建议修复：检查任务生成逻辑是否完整
```

**示例 2（P1）：**

```text
页面：/cases
操作：打开产业案例页面
期望结果：案例卡片正常显示
实际结果：顶部"产业案例"标题文字与背景色对比度不够，看起来像"产业案例"混在一起
截图/报错：见附件
严重程度：P1
是否阻塞展示：否
建议修复：增加标题与副标题之间的间距
```

**示例 3（P2）：**

```text
页面：/tools
操作：打开生物工具箱
期望结果：工具列表正常展示
实际结果：工具卡片 hover 效果不够明显
截图/报错：无
严重程度：P2
是否阻塞展示：否
建议修复：增加 hover 阴影或边框变化
```

## 四、推荐优先测试案例

以下案例建议在测试时优先体验，覆盖核心功能点：

| 案例 | caseId | 覆盖知识点 | 推荐原因 |
|---|---|---|---|
| mRNA 疫苗递送技术 | case-004 | 中心法则、mRNA 翻译、LNP | 热点技术，文献丰富，演示效果好 |
| CAR-T 细胞治疗 | case-002 | T 细胞受体、免疫突触 | 免疫治疗经典案例，科研任务丰富 |
| CRISPR 基因编辑 | case-005 | Cas9、sgRNA、DNA 修复 | 诺奖技术，文献支撑效果最佳 |
| 细胞凋亡与抗肿瘤药物 | case-001 | 细胞凋亡、Bcl-2、Venetoclax | 药物研发经典案例，科研逻辑清晰 |
| PD-1/PD-L1 免疫检查点 | case-003 | 免疫检查点、Keytruda | 广谱免疫治疗，适合展示知识迁移 |

## 五、反馈收集方式

建议统一使用以下方式收集反馈：

- **文档方式**：在共享文档中按反馈格式逐条记录
- **即时反馈**：发现问题立即在群里反馈，标注 P0/P1/P2
- **集中评审**：测试完成后汇总所有反馈，按优先级排序修复

---

## 六、注意事项

1. **测试环境**：确保前后端均已正常启动
2. **网络环境**：文献检索依赖外部服务（Semantic Scholar / CrossRef / PubMed），需确保网络可达
3. **数据状态**：测试前建议执行 `bash scripts/reset_demo_db.sh` 重置 demo 数据库
4. **不修改后端**：本轮测试以体验反馈为主，不修改后端业务逻辑
5. **截图保存**：P0 和 P1 问题建议附带截图，方便快速定位
